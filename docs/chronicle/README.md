# The Portico chronicle

**Purpose (owner request, 2026-11-07 16:34 UTC):** record exactly how Portico is being built, from the very first
message. That means:
- who oversees;
- which agents work on what;
- what was studied;
- what was built first, and why;
- what went wrong and how it was caught.

At the end it becomes the raw material for a process document, case study, success story and origin story. **Keep as
many data points as possible.** It is cheaper to drop data later than to reconstruct it.

## What is here

| File | What it holds | How it is produced |
|---|---|---|
| `01-timeline.md` | The story in order, with UTC times, phases, pauses and turning points | Written by the orchestrator; appended after every significant event |
| `02-operating-model-and-cast.md` | Who does what: owner, orchestrator, steward, module builders, researchers, reviewers, testers. Plus the full roster of agent runs | Written; roster regenerated from `data/agents.json` |
| `03-owner-directions.md` | **Every owner message and answer, verbatim**, in order | Generated by `tools/chronicle/extract.py` |
| `04-turning-points-and-lessons.md` | Decisions, surprises, bugs caught by reviews, process lessons | Written; appended as they happen |
| `05-metrics.md` | Headline numbers over time: code, tests, commits, findings, usage | Written from `data/snapshots/*.json` |
| `agents/*.md` | **Every agent run: its brief (verbatim), follow-up messages and final report(s) (verbatim)**, with start/end times, turns, tool uses and tokens | Generated by `tools/chronicle/extract.py` |
| `data/owner-messages.json`, `data/owner-answers.json` | Raw owner inputs with timestamps | Generated |
| `data/agents.json` | Machine-readable roster of agent runs | Generated |
| `data/session-stats.json` | Orchestrator activity counts (messages, tool use by tool) | Generated |
| `data/snapshots/<UTC>.json` | Point-in-time facts: commits, merges, lines of code and tests per package, docs, ADRs, open questions, review verdicts and finding counts, test results | Generated by `tools/chronicle/snapshot.py` |

Related permanent records the chronicle points to rather than copies:
- `docs/orchestration/STATUS.md` (resume log)
- `docs/orchestration/reviews/` (every steward review in full)
- `docs/product/decisions.md` (owner decisions D1–D13)
- `docs/adr/` (architecture decisions)
- `docs/OPEN_QUESTIONS.md`
- `docs/research/` (everything studied)
- `docs/ux/` (UX loop rounds)
- the git history (every commit carries a Claude-Session trailer)

## How it is maintained (orchestrator duty)

1. **After every merge to main, review verdict, owner direction, pause/resume or other turning point:** append to
   `01-timeline.md`, and to `04-turning-points-and-lessons.md` when something was learned.
2. **At every merge batch and every usage checkpoint:**
   - `python3 -I tools/chronicle/extract.py <session transcript .jsonl> .` refreshes owner messages and agent runs. It
     is idempotent, and the transcript is `~/.claude/projects/<project>/<session>.jsonl`.
   - `python3 -I tools/chronicle/snapshot.py [turbo test log]` adds a metrics snapshot. Pass the latest full test log
     so test counts are captured.
3. Commit with `docs(chronicle): …` and push. Agent transcripts live in the container and are lost when it is
   reclaimed, so **extract before every pause**.
4. Nothing is deleted or rewritten after the fact. Corrections are appended with a date.

**Known gaps in the record:**
- Full logs of agent runs from the first container (before 11:11 UTC on 2026-11-07) are not preserved. For those
  runs the record holds the brief and final report, taken from the orchestrator's transcript, but not every step.
- The orchestrator's own reasoning is summarised in the timeline, not reproduced.

Privacy: no secrets, credentials or personal data belong here. The owner's messages are kept verbatim because the
owner asked for this record. Before anything is published externally, review the verbatim files.
